# 第一章 导论：为什么要写自己的操作系统

## 一、为什么要从零写一个操作系统

你可能已经写过不少应用程序。无论是 Web 后端、移动 App 还是桌面软件，它们都运行在一个操作系统之上。操作系统为你管理内存、调度进程、读写文件、处理网络——你只需要调用几个 API，剩下的事情似乎"自然而然"就发生了。

但这些 API 背后到底发生了什么？当你调用 malloc 的时候，内存是从哪里来的？当你创建一个线程的时候，CPU 是如何在多个线程之间切换的？当你读写文件的时候，数据是如何从磁盘流动到你的缓冲区的？当你的程序崩溃的时候，操作系统是怎么知道并把它杀掉的？

这些问题的答案，都藏在操作系统内核里。而理解内核最好的方式，不是读一本又一本的教材，而是自己动手写一个。教科书会告诉你"进程是资源分配的单位"，但只有当你亲手定义了进程控制块、实现了上下文切换、看着两个进程在你的调度器下交替运行的时候，这句话才真正有了意义。

### （一）写操作系统能学到什么

写一个操作系统内核，是计算机科学中最有价值的实践项目之一。它会迫使你同时理解多个层次的系统，而这些层次在日常的应用开发中是完全透明的。

在硬件层，你需要了解 CPU 的工作模式、寄存器组织、中断机制、内存管理单元、定时器和串口等外设。你会第一次直接和硬件对话，往一个特定的物理地址写入一个字节，然后看到串口输出了一个字符。这种直接操控硬件的感觉，是调用高层 API 永远无法体会的。

在体系结构层，你会理解 ARM64 的异常级别模型、虚拟地址转换的完整过程、缓存一致性的含义、异常向量表的工作方式。这些概念在应用层永远不会接触到，但它们是一切软件运行的基础。当你理解了 MMU 如何把虚拟地址翻译成物理地址之后，再回头看"进程有独立地址空间"这句话，你会明白它背后是每一次内存访问都经过的页表遍历。

在操作系统层，你会实现物理内存分配器、虚拟内存管理、进程调度器、系统调用接口、文件系统等核心组件。每一个组件都有其设计权衡，你会在实践中体会这些权衡。比如，你会发现简单的轮转调度器很好写，但要保证公平性和响应性就需要复杂的数据结构；你会发现位图分配器很直观，但内存碎片化会让它在长期运行后变得低效。

在工程层，你会学习如何在没有标准库的环境下编写 C 代码，如何用链接脚本精确控制程序在内存中的布局，如何用汇编和 C 混合编程，如何用 QEMU 和 GDB 调试一个连 printf 都没有的程序。你会学会在系统完全挂起、没有任何输出的时候，通过查看寄存器和内存来定位问题。这些工程技能会让你在任何底层开发场景下游刃有余。

这些知识合在一起，会让你对整个计算机系统有一个完整的、从硅片到应用的全景理解。这种理解会让你成为一个更好的程序员，无论你将来做什么方向的开发。当你遇到性能问题、内存问题、并发问题的时候，你能够穿透层层抽象，看到底层真正发生了什么。

### （二）为什么选择 ARM64

这本书选择 ARM64（也叫 AArch64）作为目标架构，而不是更常见的 x86，是经过深思熟虑的。

ARM64 是当前和未来最重要的计算架构。从手机、平板到树莓派、苹果 Mac，再到云服务器（AWS Graviton、阿里云倚天），ARM64 已经无处不在。手机端几乎 100% 是 ARM，苹果的 Mac 已经全面转向 ARM，云端的 ARM 实例也在快速增长。学习 ARM64 比学习 x86 更有现实意义，而且这个趋势只会越来越明显。

ARM64 的架构设计比 x86 更现代、更干净。x86 有着四十多年的历史包袱，从 16 位实模式到 32 位保护模式再到 64 位长模式，层层叠加的兼容性设计让初学者眼花缭乱。分段机制、各种描述符表、不同的特权级切换方式，这些历史遗留概念在 x86 上必须了解，但在 ARM64 上根本不存在。ARM64 从零开始设计，异常级别模型清晰统一，指令集规整正交，内存管理只有分页一种方式，非常适合学习。

QEMU 对 ARM64 的 virt 虚拟平台提供了很好的支持。这个平台模拟了一个基于 ARM Cortex-A 系列处理器的通用虚拟机，包含 PL011 串口、GIC 中断控制器、通用定时器等标准外设。它不对应任何真实硬件，但正因为如此，它的设计非常干净，没有真实硬件的各种怪癖和限制。我们不需要购买任何硬件，在普通 PC 上就能完成所有实验，而且每个人的环境完全一致。

### （三）为什么选择 QEMU

QEMU 是一个开源的硬件模拟器和虚拟化平台。它可以模拟多种 CPU 架构和机器类型，让你在 x86 电脑上运行 ARM64 代码。它既是一个完整的系统模拟器（模拟整个计算机），也可以作为用户态模拟器（直接运行其他架构的 Linux 程序）。

使用 QEMU 最直接的好处是零硬件成本。你不需要购买开发板或 ARM 电脑，不需要连接串口线，不需要配置网络。一台普通的 x86 PC，安装 QEMU 之后就可以开始开发。对于学习来说，这大大降低了入门门槛。

QEMU 的调试体验非常友好。它内置 GDB 服务器支持，你可以用 GDB 单步调试内核代码，查看所有寄存器和内存状态，在任何地址设置断点。在真实硬件上调试内核需要 JTAG 调试器，配置复杂且价格昂贵，而 QEMU 让这一切变得简单。当你的内核在启动阶段挂起时，GDB 可以让你精确地看到程序执行到了哪一条指令、寄存器的值是什么。

QEMU 环境还是完全可复现的。每个人的 QEMU 模拟出来的硬件都是一样的，代码可以在任何地方运行，不会因为硬件差异、批次不同、固件版本不同而出现奇怪的问题。这对于教学和协作非常重要——你遇到的问题，别人也能复现；别人的解决方案，在你这里也同样有效。

当然，模拟器和真实硬件有差异。QEMU 对一些边缘情况的模拟可能不精确，性能特性也和真实硬件不同。但对于学习操作系统核心概念来说，QEMU 提供的环境已经足够真实。当你理解了原理之后，迁移到真实硬件上主要是适配驱动的工作，核心机制是完全一样的。

## 二、这本书能带你走到哪里

读完这本书并完成所有练习后，你将拥有一个自己写的、可以在 QEMU ARM64 上运行的操作系统内核。它不会像 Linux 那样功能完备，不会有几万个驱动，不会支持图形界面，但它会包含一个现代操作系统的核心组件：启动、异常中断、物理内存管理、进程调度（含优先级抢占）、fork/exec 多进程、16 个系统调用、设备驱动、文件系统、用户 Shell 以及精简网络栈。你会理解每一个组件的工作原理，因为每一行代码都是你自己写的。

### （一）你将实现的功能

具体来说，你将从零实现一整套操作系统核心功能。在启动与初始化方面，你会从汇编入口开始，初始化 CPU 状态，处理异常级别降级，设置内核栈，清零 BSS 段，然后跳转到 C 语言内核主函数。你会理解从上电到 C 代码执行之间的每一步，这是很多程序员从未接触过的黑暗地带。

在串口驱动方面，你会实现 PL011 UART 驱动，让内核可以输出文字到控制台。这是你和内核沟通的第一座桥梁，也是后续所有调试输出的基础。你会从最简单的轮询方式开始，逐步升级到中断驱动的收发。

在异常与中断方面，你会设置异常向量表，处理同步异常、IRQ、FIQ 和 SError 四类异常。你会配置 GIC 中断控制器，实现中断处理函数的注册机制，让外设可以通过中断通知 CPU。你会理解中断的完整生命周期——从硬件触发到 CPU 响应，从向量表跳转到处理函数执行，再到中断结束返回。

在物理内存管理方面，你会实现页分配器，管理系统的物理内存，支持页的分配和回收。你会理解内存布局、保留区域、页对齐这些概念，为后续的虚拟内存打下基础。

在内存布局与 MMU 设计方面，你会深入理解 ARM64 的物理内存布局：页分配器管理的 128MB 内核区、用户程序槽位区、内核镜像与 MMIO 设备的地址规划。v0.3 采用恒等映射模型（暂不开启 MMU），用"物理分区 + PC 相对寻址"实现用户程序的可搬移加载，同时讲清特权级隔离（EL1/EL0）与地址空间隔离（MMU）的区别，以及未来开启 MMU 的完整路径（TTBR/TCR/MAIR/页表）。

在内核内存分配器方面，你会在页分配器之上实现 slab 分配器，支持任意大小的动态内存分配和释放。你会理解内部碎片和外部碎片的区别，学习如何用对象缓存提高分配效率。

在进程管理方面，你会定义进程控制块，实现上下文切换，让内核可以同时运行多个执行流。你会用汇编实现寄存器的保存和恢复，理解进程切换的本质就是栈和寄存器的切换。

在调度器与定时器方面，你会配置 ARM 通用定时器产生周期性中断，实现基于时间片的抢占式调度。你会理解协作式调度和抢占式调度的区别，实现进程的睡眠和唤醒。

在系统调用方面，你会实现 SVC 异常处理，建立系统调用表，让用户程序可以通过 svc 指令请求内核服务。你会理解用户态和内核态切换的完整过程，包括寄存器的保存恢复、特权级的转换、返回值的传递。

在同步原语方面，你会用 ARM64 的原子指令实现自旋锁，实现信号量和互斥锁，解决多进程环境下的竞态条件。你会理解内存屏障的必要性，学习死锁的产生和预防。

在设备驱动模型方面，你会建立统一的字符设备和块设备接口，实现 UART 字符设备和内存模拟块设备。你会理解操作系统如何用统一的接口抽象千差万别的硬件。

在文件系统方面，你会设计简化的 VFS 层，实现内存文件系统 tmpfs，支持文件的创建、读写和目录操作。你会理解 inode、目录项、路径解析这些核心概念。

在用户空间与 Shell 方面，你会实现用户进程的创建和加载，编写用户态系统调用封装，实现一个简单的命令行解释器。你会看到自己写的用户程序运行在 EL0，通过系统调用和内核交互。

把这些功能整合起来，你就有了一个可以启动、可以多任务、可以管理内存和文件、可以和用户交互的完整操作系统。

### （二）它不会做什么

同样重要的是，要明确这本书不会覆盖什么。这不是一本 Linux 内核源码分析书，也不是一本操作系统理论教材，我们的目标是动手实践，而不是面面俱到。

我们不会实现 POSIX 兼容层。我们的系统调用接口会很简单，不会和 Linux 的系统调用号一一对应，也不会实现 Linux 的所有系统调用。我们不会实现信号、管道、共享内存、消息队列等进程间通信机制。这些都是可以在我们的框架上继续添加的功能。

我们不会深入讨论每一个主题的所有细节。比如调度器，我们只实现静态优先级抢占调度，不会讨论 CFS、实时调度、SMP 负载均衡、Deadline 调度器这些 Linux 中的复杂机制。比如文件系统，我们只实现一个内存文件系统 tmpfs，不会讨论 ext4 的块分配、日志、快速符号链接、目录索引等高级特性。

我们的网络实现是精简版。我们实现了 virtio-net 网卡探测初始化、ARP/IP/ICMP/UDP 协议栈和 16 个 UDP socket，但不实现 TCP、拥塞控制、路由表等更复杂的部分——这些留作扩展方向。

我们不会实现动态链接和共享库。用户程序都是静态链接的，不需要动态加载器。我们也不会实现可加载内核模块，所有功能都编译进内核镜像。

这些省略是有意的。操作系统是一个极其庞大的领域，一本书不可能覆盖所有内容。我们的目标是建立一个清晰的骨架，让你理解每个核心组件的工作原理。有了这个骨架，你可以自己继续添加任何感兴趣的功能——而且因为你理解了核心机制，添加新功能会变得容易很多。

### （三）和真实 Linux 的关系

虽然我们写的不是 Linux，但我们的设计会大量参考 Linux 的思路。很多数据结构和算法的命名会和 Linux 保持一致，比如 task_struct、page、mm_struct 这些名字，你在阅读 Linux 源码时会看到同样的概念。

但我们的实现会比 Linux 简单得多。Linux 要考虑各种硬件兼容性、性能优化、错误处理、安全边界、向后兼容，这些都会让代码变得复杂。一个简单的调度器在 Linux 中可能有几千行代码，因为要处理各种边界情况和优化场景。我们只需要在 QEMU 的 virt 平台上工作，可以忽略很多边缘情况，把注意力集中在核心机制上。

可以把这本书的内核看作是 Linux 内核的一个教学版简化模型。它保留了核心思想和基本结构，但去掉了所有工程上的复杂性。当你以后去读 Linux 源码的时候，会发现很多概念似曾相识——我们的进程控制块对应 Linux 的 task_struct，我们的内存分配器对应 Linux 的伙伴系统和 slab，我们的中断处理对应 Linux 的 irq_desc 和 request_irq。理解了简化版，再看完整版就有了框架。

## 三、前置知识与准备

### （一）你需要知道什么

这本书假设你有一些基础，但不需要任何操作系统开发经验。

你应该熟悉 C 语言编程。理解指针、数组、结构体、函数指针、宏、volatile 关键字这些概念。内核编程几乎全部使用 C，我们不会花时间讲解 C 语言基础。如果你能看懂链表、哈希表的 C 实现，能理解指针运算，那就足够了。

你应该有基本的计算机组成原理知识。知道 CPU、内存、外设的基本概念，理解寄存器、地址总线、数据总线的含义，知道程序是怎么被 CPU 执行的。你不需要深入理解数字电路或处理器微架构，但应该对"CPU 从内存取指令执行"这个模型有基本概念。

你应该听说过基本的操作系统概念。进程、线程、虚拟内存、系统调用、文件系统这些名词应该不陌生。我们会在实现它们的时候详细讲解工作原理，但如果你完全没听说过，可能会觉得节奏偏快。如果是这样，可以先读一本操作系统入门教材的前几章，建立基本概念。

你应该有命令行使用经验。我们会在 Linux 环境下开发，大量使用命令行工具和 Makefile。你应该熟悉基本的 shell 命令，知道怎么编译程序、怎么查看文件、怎么用编辑器写代码。

如果你缺少其中某一项，也不必担心。C 语言和计算机组成原理可以通过很多优秀的教材快速补习。操作系统概念可以边做边学——事实上，动手实现是理解这些概念最好的方式，比单纯读书要有效得多。

### （二）你不需要知道什么

你不需要有任何汇编语言经验。我们会在用到的时候讲解必要的 ARM64 汇编指令，而且大部分代码都是 C 语言。你只需要能看懂简单的汇编代码，不需要能熟练编写。

你不需要有操作系统开发经验。这本书就是为从零开始的人设计的。每一步都会解释为什么这么做，不会假设你已经知道什么。

你不需要有 ARM 架构的知识。第三章会专门讲解 ARM64 架构基础，包括寄存器、异常级别、指令集、内存模型等。后续章节用到具体特性时也会详细解释。

你不需要一台 ARM 电脑。所有开发和运行都在 x86 PC 上通过 QEMU 完成。你甚至不需要 Linux 实体机——用虚拟机或 WSL2 都可以。

### （三）开发环境

我们将在 Linux 环境下开发。推荐使用 Ubuntu 20.04 或更新版本，其他发行版（Debian、Fedora、Arch 等）也可以，只是包名和安装命令可能略有不同。

你需要安装交叉编译工具链（aarch64-linux-gnu-gcc），用于把 C 代码编译成 ARM64 机器码。需要 QEMU（qemu-system-aarch64）来运行和调试内核。需要 GDB（gdb-multiarch）来调试 ARM64 程序。还需要 Make、设备树编译器等辅助工具。第二章会详细讲解如何安装和配置这些工具。

如果你使用的是 macOS，可以用 Homebrew 安装 ARM 交叉编译工具链和 QEMU。如果你使用 Windows，建议安装 WSL2（Windows Subsystem for Linux），在 WSL2 中运行 Ubuntu，然后按照 Linux 的步骤操作。直接在 Windows 上开发会遇到很多兼容性问题，不推荐。

## 四、本书的组织结构

本书共 19 章，按照从简单到复杂、从底层到上层的顺序组织。每一章都建立在前一章的基础之上，逐步为内核添加新功能。你可以把每一章看作一个里程碑，完成后就有一个可以运行的、比之前功能更丰富的内核。

第一部分是基础与环境，包括前三章。第一章是导论，介绍为什么要写操作系统、本书的目标和组织结构。第二章讲解开发环境搭建，安装交叉编译工具链、QEMU 和 GDB，学习如何用 QEMU 运行程序、如何用 GDB 调试。第三章讲解 ARM64 架构基础，包括寄存器、异常级别、指令集、内存模型和调用约定，这是后续所有章节的基础。

第二部分是最小内核，包括第四到第六章。第四章实现第一个裸机程序，编写 UART 驱动输出 Hello World。第五章完善启动代码和链接脚本，处理异常级别降级，建立完整的 C 运行时环境，并把用户程序内嵌进内核镜像。第六章实现异常和中断处理，设置异常向量表，配置 GIC，让内核能够响应硬件中断和系统调用。

第三部分是内存管理，包括第七到第九章。第七章实现物理内存管理，用位图分配器管理 128MB 物理内存。第八章讲解内存布局与 MMU 设计——当前构建采用恒等映射（MMU 未启用），重点讲清用户槽位区隔离与未来的 MMU 开启路径。第九章在内核页分配器之上实现 slab 动态内存分配器。

第四部分是进程与调度，包括第十到第十二章。第十章实现进程管理，定义进程控制块，用汇编实现上下文切换，实现用户进程创建与 fork/exec。第十一章实现调度器和定时器，用定时器中断实现优先级抢占式多任务，实现睡眠唤醒与僵尸回收。第十二章实现系统调用，建立用户态和内核态之间的桥梁。

第五部分是 I/O 与文件系统，包括第十三到第十五章。第十三章实现同步原语，包括自旋锁和信号量。第十四章建立设备驱动模型，统一字符设备和块设备接口。第十五章实现文件系统，设计 VFS 层并编写内存文件系统 tmpfs。

第六部分是综合与进阶，包括第十六到第十九章。第十六章实现用户空间和简单的 Shell，展示 fork/exec/wait 的多进程模型。第十七章是综合实验，把所有组件整合起来运行完整的用户程序。第十八章实现网络支持，适配现代 QEMU 的 PCIe，实现 virtio-net 驱动与 ARP/IP/ICMP/UDP 协议栈。第十九章总结全书，讨论和真实 Linux 的差距，以及继续深入学习的方向。

## 五、如何使用这本书

### （一）边读边写

这本书不是用来"读"的，是用来"做"的。每一章都有完整的代码示例，你应该跟着敲一遍，而不是只看不练。

操作系统开发的很多知识是"肌肉记忆"。你只有亲手写过启动代码、调试过页表错误、踩过上下文切换的坑，才能真正理解这些概念。看别人写的代码和自己写一遍，收获完全不同——就像看别人游泳和自己下水游的区别。

建议的学习方式是：每读完一节，就把对应的代码写出来，编译运行，确认结果和书上一致。如果遇到问题，先自己调试——用 GDB 单步执行，查看寄存器和内存，思考为什么和预期不一样。实在解决不了再参考完整代码。这个调试的过程本身就是最好的学习。

### （二）代码组织

每一章的代码都建立在前一章的基础上。建议你为每一章创建一个单独的目录，比如 chapter04、chapter05，这样可以保留每个阶段的完整代码，方便回溯和对比。当你在某一章把代码改坏了，可以回到上一章的版本重新开始。

也推荐使用 Git 管理代码，每完成一章就提交一次。这样可以清楚地看到每一步添加了什么，出了问题也可以用 git diff 对比改动，用 git checkout 回退。写提交信息的时候简单描述一下这一章实现了什么，以后回看的时候会很有帮助。

### （三）调试是常态

写内核和写应用程序最大的区别是：出错的时候你看不到错误信息。没有段错误提示，没有异常栈追踪，没有 core dump。很多时候系统就是直接重启或者完全挂起，屏幕上什么都没有。

你需要学会使用 QEMU 和 GDB 来调试。单步执行、查看寄存器、检查内存、设置断点、反汇编，这些是你最常用的工具。第二章会详细讲解调试方法，后续章节也会不断强化这些技能。

不要因为调试困难而气馁。每一个你花几个小时解决的 bug，都会让你对系统的理解深入一层。这是操作系统开发最有价值的部分——当你终于找到那个因为少了一条内存屏障指令而导致的随机崩溃时，你对内存模型的理解会比读十遍教材都深刻。

### （四）扩展与实验

每一章的末尾会有一些扩展练习，建议你在完成基础内容后尝试。这些练习会让你在已有代码的基础上添加新功能或改进现有实现，是深入理解的最佳方式。

比如，实现了基本的调度器之后，可以尝试添加优先级调度或完全公平调度。实现了内存文件系统之后，可以尝试实现一个持久化的块设备文件系统。实现了单核调度之后，可以尝试支持多核。这些扩展没有标准答案，你可以自由探索，遇到问题再去查资料。

## 六、开始之前

在开始第二章之前，让我们确认几件事。你有一台可以运行 Linux 的电脑，无论是原生 Linux、虚拟机还是 WSL2 都可以。你有至少几个 GB 的空闲磁盘空间用于安装工具链和存放代码。你有足够的时间和耐心——写一个操作系统不是一个周末就能完成的项目，预计需要几周到几个月的业余时间。但每一步都会有明确的成果，你会持续获得成就感。

最重要的是，你有探索的热情。操作系统开发充满了未知和惊喜，当你第一次看到自己写的内核在 QEMU 中输出文字、第一次实现进程切换看到两个程序交替运行、第一次看到用户程序通过系统调用请求内核服务的时候，那种喜悦是无与伦比的。

准备好了吗？让我们从搭建开发环境开始，踏上从零编写操作系统的旅程。记住，每一行代码都是你对计算机系统理解的深化，每一个 bug 都是成长的阶梯。
