# 第三章 ARM64 架构基础

## 一、概述

在开始写内核之前，我们需要对目标架构有足够的了解。ARM64（也称为 AArch64）是 ARM 公司推出的 64 位指令集架构，和 32 位的 ARM（AArch32）有显著区别。它设计得更加现代和规整，去掉了很多历史包袱。

这一章会讲解 ARM64 编程中最核心的几个概念：通用寄存器和特殊寄存器、异常级别模型、常用汇编指令、内存模型以及函数调用约定。理解这些内容后，你就能看懂后续章节中的汇编代码，也能自己编写底层汇编例程。

## 二、通用寄存器

ARM64 有 31 个通用寄存器，编号为 X0 到 X30，每个都是 64 位宽。在 32 位模式下使用它们的低 32 位时，称为 W0 到 W30。

这些寄存器在函数调用中有约定俗成的分工。X0 到 X7 用于传递函数参数，X0 也用于存放返回值。X8 是间接结果寄存器（也用于系统调用号）。X9 到 X15 是临时寄存器，函数调用时不需要保存。X16 和 X17 是过程调用内临时寄存器（IP0、IP1），链接器可能会使用它们。X18 是平台寄存器，某些平台会保留使用。

X19 到 X28 是被调用者保存寄存器。如果一个函数使用了这些寄存器，它必须在返回前恢复它们的原值，这样调用者才能依赖这些寄存器在函数调用前后保持不变。X29 是帧指针（FP），用于建立栈帧。X30 是链接寄存器（LR），保存函数调用的返回地址。

除了这 31 个寄存器，还有一个零寄存器 XZR（WZR），它的值永远是 0，读的时候返回 0，写的时候丢弃。这个设计很巧妙，很多指令可以利用零寄存器简化代码。比如把一个寄存器清零可以用 `mov x0, xzr`，比较一个寄存器是否为 0 可以用 `cmp x0, xzr`。

栈指针寄存器 SP 比较特殊。在 ARM64 中，SP 不是通用寄存器，它有自己的编号。在异常级别 EL1 及以上，可以选择使用 SP_EL0（用户态栈指针）或 SP_ELx（当前异常级别的栈指针）。内核通常使用 SP_EL1 作为内核栈，这样进入异常时自动切换到内核栈。

程序计数器 PC 也不能直接访问，不能像通用寄存器那样读写。要修改 PC，只能通过分支指令（B、BL、BR）或异常返回指令（ERET）。要读取 PC，可以用 ADR 或 ADRP 指令获取当前地址附近的标签地址。

## 三、异常级别模型

ARM64 的特权模型称为异常级别（Exception Level），编号从 EL0 到 EL3，数字越大特权越高。这和 x86 的 Ring 0-3 类似，但设计更清晰。

EL0 是用户级，权限最低，运行应用程序。在 EL0 下，很多系统寄存器不能访问，MMU 开启后只能访问用户空间的虚拟地址。应用程序如果需要内核服务，必须通过 SVC 指令触发异常，陷入到 EL1。

EL1 是内核级，运行操作系统内核。在 EL1 下可以访问所有硬件资源，配置 MMU、中断控制器、定时器等。我们的内核大部分时间运行在 EL1。

EL2 是虚拟化级，运行虚拟机监控器（Hypervisor）。它可以创建和管理虚拟机，让多个客户操作系统共享硬件。在 QEMU 中，如果不使用虚拟化，CPU 启动时可能处于 EL2，我们需要主动降级到 EL1。

EL3 是安全监控级，是最高特权级别，负责安全世界（Secure World）和正常世界（Normal World）之间的切换。ARM 的 TrustZone 技术就在这一层实现。大多数应用处理器都有 EL3，但在 QEMU 的 virt 平台上，默认配置下 CPU 可能直接从 EL2 或 EL1 启动，不经过 EL3。

每个异常级别都有自己的一组银行寄存器（banked registers），包括 SP_ELx、ELR_ELx（异常链接寄存器，保存异常返回地址）、SPSR_ELx（保存的程序状态寄存器）、SCTLR_ELx（系统控制寄存器）等。这样在异常发生时，当前级别的关键状态会被硬件自动保存，不会被低级别代码破坏。

异常只能从低级别陷入到高级别，或者在同级别内发生。比如 EL0 的应用程序触发 SVC，会陷入 EL1；EL1 的内核代码触发异常，仍然在 EL1 处理。异常返回时通过 ERET 指令，可以返回到原来的异常级别。

在我们的内核中，主要关注 EL0 和 EL1。EL2 和 EL3 只在启动初始化时短暂接触——如果 CPU 启动在 EL2，我们需要做一些基本配置然后降级到 EL1。

## 四、系统寄存器

ARM64 有大量的系统寄存器（System Registers），用于控制 CPU 的各种功能。这些寄存器不能像通用寄存器那样直接使用，必须通过 MRS（读系统寄存器）和 MSR（写系统寄存器）指令访问。

系统寄存器的命名通常带有异常级别后缀，比如 TTBR0_EL1 表示 EL1 级别的 TTBR0 寄存器。有些寄存器在多个级别都存在，各自独立。

下面介绍几个最常用的系统寄存器。

CurrentEL 寄存器保存当前的异常级别，只读。它的第 2-3 位表示当前 EL，比如 EL1 对应值为 4（二进制 0100，第 2 位为 1）。启动代码可以读这个寄存器来判断当前处于哪个异常级别。

SCTLR_EL1（系统控制寄存器）是最核心的控制寄存器之一。它的第 0 位（M 位）控制 MMU 的开启和关闭，第 2 位（C 位）控制数据缓存，第 12 位（I 位）控制指令缓存。本书 v0.3 采用恒等映射模型，**暂不开启 MMU**（SCTLR 的 M 位保持 0）；第 8 章会讲解内存布局设计与未来开启 MMU 的完整路径（届时配置好页表后再把 M 位置 1）。

SPSR_EL1（保存的程序状态寄存器）在异常发生时，硬件会把发生异常前的 PSTATE（处理器状态）保存到这里。PSTATE 包含条件标志位（N、Z、C、V）、中断掩码位（DAIF）、当前异常级别等信息。异常返回时，ERET 指令会从 SPSR_EL1 恢复 PSTATE。

ELR_EL1（异常链接寄存器）保存异常返回地址。当异常发生时，硬件把被中断指令的下一条指令地址存入 ELR_EL1。ERET 指令会把 ELR_EL1 的值恢复到 PC，实现异常返回。

VBAR_EL1（向量基地址寄存器）保存异常向量表的基地址。我们需要把自己编写的异常向量表地址写入这个寄存器，这样异常发生时 CPU 才能找到对应的处理函数。

TTBR0_EL1 和 TTBR1_EL1 是翻译表基地址寄存器，分别保存用户空间和内核空间页表的物理基地址。MMU 根据虚拟地址的高位决定使用哪个页表。TCR_EL1（翻译控制寄存器）配置地址空间大小、页表粒度、缓存属性等。MAIR_EL1（内存属性间接寄存器）定义内存区域的属性，比如普通内存还是设备内存、是否可缓存等。这三个寄存器是配置 MMU 的关键，第八章会详细讲解。

CNTPCT_EL0 保存当前物理计数值，CNTFRQ_EL0 保存定时器的频率。CNTP_TVAL_EL1 和 CNTP_CTL_EL1 用于配置物理定时器。CNTV_TVAL_EL0 和 CNTV_CTL_EL0 用于配置虚拟定时器。第十一章实现时钟中断时会用到这些寄存器。

DAIF 是 PSTATE 中的中断掩码位，D 是调试异常掩码，A 是 SError 掩码，I 是 IRQ 掩码，F 是 FIQ 掩码。某一位置 1 表示屏蔽该类异常。可以用 MSR 指令直接修改 DAIF，比如 `msr daifset, #2` 屏蔽 IRQ，`msr daifclr, #2` 开启 IRQ。

## 五、常用汇编指令

ARM64 的指令集是固定长度的，每条指令 4 字节（32 位）。指令格式规整，大多数指令遵循"目的操作数在前，源操作数在后"的约定。

数据处理指令中，MOV 指令用于在寄存器之间传送数据，或者把立即数加载到寄存器。比如 `mov x0, x1` 把 X1 的值复制到 X0，`mov x0, #10` 把立即数 10 加载到 X0。注意立即数的范围有限，太大的数需要用 MOVZ、MOVK 组合加载。

ADD 和 SUB 是加法和减法。`add x0, x1, x2` 计算 X1 + X2，结果存入 X0。也可以加立即数，`add x0, x1, #16`。还可以带移位操作，`add x0, x1, x2, lsl #3` 表示 X1 + (X2 << 3)。

MUL 是乘法，`mul x0, x1, x2` 计算 X1 * X2。SDIV 和 UDIV 分别是有符号和无符号除法。ARM64 没有除法余数指令，需要用乘法和减法计算余数。

AND、ORR、EOR 是按位与、或、异或。BIC 是按位清零（和取反后的数相与）。这些指令常用于操作寄存器的特定位。比如 `orr x0, x0, #(1 << 0)` 把第 0 位置 1，`and x0, x0, #~(1 << 0)` 把第 0 位清零。

LSL、LSR、ASR 是逻辑左移、逻辑右移、算术右移。可以作为独立指令，也可以作为其他指令的移位操作数。

加载和存储指令用于在寄存器和内存之间传送数据。LDR 从内存加载到寄存器，`ldr x0, [x1]` 把 X1 指向的内存地址中的 64 位数据加载到 X0。STR 把寄存器数据存储到内存，`str x0, [x1]`。可以带偏移，`ldr x0, [x1, #8]` 从 X1+8 地址加载。还可以写回偏移，`ldr x0, [x1], #8` 加载后 X1 自动加 8。

LDP 和 STP 是加载/存储一对寄存器，常用于函数入口和出口保存和恢复寄存器。比如 `stp x29, x30, [sp, #-16]!` 把 X29 和 X30 压栈，同时 SP 减 16。对应的 `ldp x29, x30, [sp], #16` 出栈并恢复。

分支指令中，B 是无条件跳转，`b label` 跳转到标签处。BL 是带链接的跳转，把返回地址存入 LR（X30），然后跳转，用于函数调用。BR 跳转到寄存器中的地址，`br x0` 跳转到 X0 中的地址。RET 是函数返回，等价于 `br x30`。

条件分支指令根据 PSTATE 的条件标志位决定是否跳转。B.EQ 相等时跳转（Z 标志为 1），B.NE 不等时跳转，B.LT 有符号小于时跳转，B.GT 有符号大于时跳转，等等。CMP 指令比较两个寄存器，设置条件标志位，然后配合条件分支使用。

MRS 和 MSR 用于访问系统寄存器。`mrs x0, CurrentEL` 把 CurrentEL 寄存器的值读到 X0。`msr daifset, #2` 把立即数写入 DAIFSET（设置 DAIF 的特定位）。

SVC 指令触发超级用户调用异常，用于系统调用。`svc #0` 触发异常，陷入 EL1。立即数参数通常被忽略，系统调用号通过 X8 传递。

ERET 是异常返回指令，从 ELR_EL1 恢复 PC，从 SPSR_EL1 恢复 PSTATE。这是从异常处理程序返回的唯一方式。

NOP 是空操作，什么也不做，常用于对齐或占位。WFI（Wait For Interrupt）让 CPU 进入低功耗状态，等待中断发生。空闲循环中常用 WFI 节省 CPU。

## 六、内存模型

ARM64 使用弱内存模型（Weakly Ordered Memory），这意味着 CPU 可能会重排内存访问指令的执行顺序，以提高性能。在单线程执行中，重排不会影响结果（CPU 保证程序顺序的语义），但在多核心或设备 DMA 场景下，重排可能导致问题。

为了处理这个问题，ARM64 提供了内存屏障指令。DMB（Data Memory Barrier）保证在它之前的所有内存访问都完成后，才会执行它之后的内存访问。DSB（Data Synchronization Barrier）更强，保证之前的所有内存访问完成，并且所有缓存、TLB 维护操作完成。ISB（Instruction Synchronization Barrier）刷新指令流水线，保证之后的指令重新从缓存或内存取指。

这些屏障在多核同步、修改页表后刷新 TLB、开启 MMU 等场景下必须使用。比如修改 TTBR 后需要 DSB 保证更新生效，然后 ISB 刷新指令流水线。

内存属性方面，ARM64 通过 MAIR 寄存器定义 8 种内存属性（索引 0-7），每个页表项通过属性索引选择对应的属性。属性定义了内存是普通内存（Normal Memory）还是设备内存（Device Memory），以及缓存策略（写回、写透、不缓存等）。

普通内存可以被缓存，CPU 可以自由重排访问，适合 RAM。设备内存不能被缓存，访问有严格的顺序要求，适合内存映射的外设寄存器（如 UART、GIC）。本书 v0.3 未开启 MMU，访问外设用直接物理地址（如 UART 的 0x09000000）；将来配置页表时，会把 RAM 区域标记为普通内存，把外设寄存器区域标记为设备内存（第 8 章给出路径）。

地址对齐方面，ARM64 要求大多数内存访问是自然对齐的。比如加载 64 位数据时地址应该 8 字节对齐，加载 32 位数据时地址应该 4 字节对齐。非对齐访问在普通内存上可能被支持（取决于 SCTLR 的配置），但在设备内存上一定不支持。写内核代码时应该注意保持地址对齐。

## 七、函数调用约定

ARM64 的函数调用约定（AAPCS64）定义了寄存器如何使用、参数如何传递、栈如何布局。理解这个约定对于写汇编和 C 混合编程非常重要。

参数传递方面，前 8 个整数或指针参数通过 X0 到 X7 传递。如果参数超过 8 个，多余的通过栈传递。浮点参数通过 V0 到 V7 传递（我们禁用了浮点，所以不涉及）。返回值通过 X0 返回，如果返回值大于 64 位（比如结构体），则 X0 指向调用者分配的内存，函数把结果写入那里。

寄存器保存方面，X0 到 X18 是调用者保存寄存器（caller-saved），函数可以随意修改，不需要恢复。如果调用者需要这些寄存器的值，它必须自己保存。X19 到 X28 是被调用者保存寄存器（callee-saved），函数如果使用了它们，必须在返回前恢复原值。X29（FP）和 X30（LR）通常也需要保存。

栈的增长方向是向下（从高地址向低地址）。栈指针对齐要求是 16 字节。函数入口通常这样建立栈帧：先把 FP 和 LR 压栈，然后把 SP 存入 FP，再分配局部变量空间。函数出口反向操作，恢复 FP 和 LR，然后 RET 返回。

一个典型的函数序言和尾声如下：

```assembly
function:
    stp x29, x30, [sp, #-16]!   // 保存 FP 和 LR，SP 减 16
    mov x29, sp                 // 设置 FP
    sub sp, sp, #32             // 分配 32 字节局部变量空间
    // ... 函数体 ...
    add sp, sp, #32             // 释放局部变量空间
    ldp x29, x30, [sp], #16     // 恢复 FP 和 LR，SP 加 16
    ret                         // 返回
```

在我们的内核中，C 编译器会自动生成符合调用约定的代码。只有在手写汇编时需要手动遵守这些约定，比如启动代码、异常向量表、上下文切换代码等。

## 八、寻址模式

ARM64 的加载/存储指令支持多种寻址模式，理解这些模式对于读写内存和外设寄存器很有帮助。

基址寻址是最简单的形式，地址就是寄存器中的值。`ldr x0, [x1]` 从 X1 指向的地址加载。

基址加偏移寻址在基址寄存器上加一个立即数偏移。`ldr x0, [x1, #8]` 从 X1+8 加载。偏移可以是正数或负数，范围取决于指令编码。

基址加变址寻址用另一个寄存器作为偏移，还可以带移位。`ldr x0, [x1, x2]` 从 X1+X2 加载。`ldr x0, [x1, x2, lsl #3]` 从 X1 + (X2 << 3) 加载，这在访问数组元素时很常用（每个元素 8 字节）。

前索引寻址（pre-index）在访问前更新基址寄存器。`ldr x0, [x1, #8]!` 先把 X1 加 8，然后从新地址加载。感叹号表示写回基址寄存器。

后索引寻址（post-index）在访问后更新基址寄存器。`ldr x0, [x1], #8` 先从 X1 加载，然后 X1 加 8。这种模式在遍历数组时非常方便。

PC 相对寻址用 ADR 和 ADRP 指令。ADR 计算当前 PC 加上一个偏移，得到标签地址，范围是 ±1MB。ADRP 计算当前 PC 所在页（4KB 对齐）加上一个页偏移，得到一个页地址，范围是 ±4GB。ADRP 通常配合 ADD 或 LDR 的立即数偏移来访问全局变量，比如 `adrp x0, variable` 然后 `add x0, x0, :lo12:variable` 获取变量的绝对地址。

PC 相对寻址与本书的 v0.3 用户程序设计有直接关系（第 8 章会详细展开）：我们的用户程序用 `-fno-pic -fno-pie` 编译，GCC 对函数调用和数据访问默认生成 PC 相对的 ADR/ADRP 指令，而不是硬编码绝对地址。这意味着程序被加载到**任意** 1MB 槽位都能正确运行——入口 PC 由内核重设，数据访问由 PC 相对偏移完成，代码不需要知道自己身在何处。这正是"无 MMU 情况下依然可以把同一份程序搬到不同槽位执行"的指令级基础。

## 九、汇编伪指令和汇编器

GNU 汇编器（GAS）支持很多伪指令，用于控制汇编过程。这些不是真正的 CPU 指令，而是给汇编器的指示。

`.section` 切换到指定的段，比如 `.section .text` 切换到代码段，`.section .data` 切换到数据段，`.section .bss` 切换到 BSS 段。还可以自定义段名。

`.global` 声明一个符号为全局可见，这样链接器可以在其他文件中引用它。比如 `.global _start` 把 `_start` 声明为入口点。

`.align` 按指定字节对齐当前位置。`.align 3` 按 8 字节对齐（2^3）。注意 GAS 的 `.align` 参数是 2 的幂次，不是直接的字节数。

`.byte`、`.hword`、`.word`、`.quad` 分别在当前位置放置 1、2、4、8 字节的数据。比如 `.quad 0x1234` 放置一个 64 位常量。

`.asciz` 放置一个以 null 结尾的字符串。`.ascii` 放置不带 null 结尾的字符串。

`.equ` 定义一个常量符号，类似 C 的 `#define`。`.equ PAGE_SIZE, 4096` 定义 PAGE_SIZE 为 4096。

`.macro` 和 `.endm` 定义宏，可以在汇编中展开重复的代码块。

`.end` 标记汇编文件结束（可选）。

在 C 代码中嵌入汇编使用 `asm` 关键字。基本的内联汇编格式是 `asm("指令" : 输出操作数 : 输入操作数 : 破坏的寄存器)`。比如读取当前异常级别可以写：

```c
unsigned long el;
asm volatile("mrs %0, CurrentEL" : "=r"(el));
```

`volatile` 关键字告诉编译器不要优化掉这段汇编，即使输出没有被使用。内联汇编在操作系统寄存器时很有用，但复杂的汇编代码最好写成独立的 `.S` 文件。

## 十、汇编编程实践

理解了指令和寻址模式之后，让我们通过几个实际的例子来巩固 ARM64 汇编编程。这些例子涵盖了常见的编程模式，你在后续的内核开发中会反复遇到。

### （一）内存复制函数

实现一个类似 memcpy 的函数，把 src 指向的 n 个字节复制到 dst：

```assembly
// void *memcpy(void *dst, const void *src, size_t n)
// x0 = dst, x1 = src, x2 = n
.global memcpy
memcpy:
    mov x3, x0          // 保存 dst 用于返回
1:
    cmp x2, #8
    b.lo 2f             // 不足 8 字节，逐字节复制
    ldr x4, [x1], #8    // 从 src 加载 8 字节，src += 8
    str x4, [x0], #8    // 存储到 dst，dst += 8
    sub x2, x2, #8
    b 1b
2:
    cbz x2, 3f          // n == 0，结束
    ldrb w4, [x1], #1   // 加载 1 字节
    strb w4, [x0], #1   // 存储 1 字节
    sub x2, x2, #1
    b 2b
3:
    mov x0, x3          // 返回 dst
    ret
```

这个例子展示了后索引寻址（ldr x4, [x1], #8）、条件分支（b.lo）、比较和循环。先按 8 字节块复制，不足 8 字节的部分逐字节复制。这是一个典型的优化策略——用大粒度操作提高效率，最后处理尾部。

### （二）字符串长度函数

实现 strlen，计算以 null 结尾的字符串长度：

```assembly
// size_t strlen(const char *s)
// x0 = s
.global strlen
strlen:
    mov x1, x0          // 保存起始地址
1:
    ldrb w2, [x1], #1   // 加载一个字节，地址加 1
    cbnz w2, 1b         // 不是 0，继续
    sub x0, x1, x0      // 计算长度 = 当前地址 - 起始地址 - 1
    sub x0, x0, #1
    ret
```

这里用了 CBNZ（Compare and Branch on Non-Zero）指令，它把比较和分支合并成一条指令，比单独的 CMP + B.NE 更高效。

### （三）位操作示例

设置和清除寄存器的特定位是内核编程中最常见的操作。比如配置 SCTLR_EL1 开启 MMU：

```assembly
// 开启 MMU、数据缓存、指令缓存
mrs x0, sctlr_el1
orr x0, x0, #(1 << 0)    // M 位：开启 MMU
orr x0, x0, #(1 << 2)    // C 位：开启数据缓存
orr x0, x0, #(1 << 12)   // I 位：开启指令缓存
msr sctlr_el1, x0
isb                      // 指令同步屏障
```

清除特定位用 BIC（Bit Clear）指令，等价于 AND 取反后的值：

```assembly
// 关闭 MMU
mrs x0, sctlr_el1
bic x0, x0, #(1 << 0)    // 清除 M 位
msr sctlr_el1, x0
isb
```

### （四）函数调用和栈帧

一个完整的函数调用例子，展示栈帧的建立和恢复：

```assembly
// int add_arrays(int *a, int *b, int n)
// 计算两个数组的和，返回总和
.global add_arrays
add_arrays:
    stp x29, x30, [sp, #-16]!   // 保存 FP 和 LR，分配栈帧
    mov x29, sp                 // 设置 FP
    stp x19, x20, [sp, #-16]!   // 保存被调用者保存寄存器

    mov x19, x0                 // 保存 a
    mov x20, x1                 // 保存 b
    mov x0, #0                  // sum = 0
1:
    cbz x2, 2f                  // n == 0，结束
    ldr w3, [x19], #4           // 加载 a[i]
    ldr w4, [x20], #4           // 加载 b[i]
    add w3, w3, w4              // a[i] + b[i]
    add w0, w0, w3              // sum += ...
    sub x2, x2, #1
    b 1b
2:
    ldp x19, x20, [sp], #16     // 恢复寄存器，释放栈空间
    ldp x29, x30, [sp], #16     // 恢复 FP 和 LR
    ret
```

这个函数使用了 x19 和 x20 来保存数组指针，因为它们是被调用者保存寄存器，函数内部可以自由使用，只要在返回前恢复。栈帧的建立和恢复遵循标准的 AAPCS64 约定。

### （五）内联汇编中的约束

在 C 代码中使用内联汇编时，需要正确指定操作数约束。最常用的约束是 "r"（任意通用寄存器）、"=r"（输出寄存器）、"i"（立即数）。

读取系统寄存器：

```c
static inline unsigned long read_currentel(void) {
    unsigned long val;
    asm volatile("mrs %0, CurrentEL" : "=r"(val));
    return val;
}
```

写入系统寄存器：

```c
static inline void write_daif(unsigned long val) {
    asm volatile("msr daif, %0" :: "r"(val));
}
```

带多个操作数的内联汇编，比如原子交换：

```c
static inline unsigned long atomic_swap(volatile unsigned long *ptr,
                                        unsigned long new_val) {
    unsigned long old_val;
    unsigned int status;
    asm volatile(
        "1: ldxr %0, [%2]\n"
        "   stxr %w1, %3, [%2]\n"
        "   cbnz %w1, 1b\n"
        : "=&r"(old_val), "=&r"(status)
        : "r"(ptr), "r"(new_val)
        : "memory"
    );
    return old_val;
}
```

这里 "=&r" 表示早期修改的输出操作数，"memory" 告诉编译器这段汇编可能修改内存，不要优化掉相关的内存访问。
